          View Environment & Credential Setup Guide

          LifePilot communicates securely with Amazon Bedrock via server-side environment variables. Credentials are never exposed to browser client code.

          Example .env configuration
          AWS_REGION=us-east-1
AWS_ACCESS_KEY_ID=your_access_key
AWS_SECRET_ACCESS_KEY=your_secret_key
# Optional for IAM roles / temporary session tokens:
# AWS_SESSION_TOKEN=your_session_token
BEDROCK_MODEL_ID=anthropic.claude-3-5-sonnet-20240620-v1:0
          • Keep real keys only in your local .env file (which is excluded from Git via .gitignore).
          • Use .env.example with placeholder values for repository sharing.
          • Temporary credentials via AWS Academy, Learner Lab, or IAM Roles with AWS_SESSION_TOKEN are fully supported.

          Troubleshooting Common Issues

          1. Missing Credentials

          If keys are not in .env, LifePilot automatically runs in Demo Mode with intelligent local planning so you can test all workflows.

          2. Insufficient Permissions

          If you receive AccessDeniedException, attach bedrock:InvokeModel and bedrock:InvokeModelWithResponseStream to your IAM policy.

          3. Model Access Not Granted

          In the AWS Console for your region (e.g. us-east-1), open Amazon Bedrock > Model access and request access for Claude 3.5 Sonnet or Nova.

          4. Network / Endpoint Timeouts

          Check your network connection and verify that your configured AWS_REGION is reachable without proxy blocks.
